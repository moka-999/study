## Flash旧记录保护

- 当前FRU保持224字节schema v2，两个旧schema v1布局按160/192字节分别识别，不能按同一偏移强转。
- 旧序列号、已有产品/硬件版本、有效MAC、IP/掩码/网关、端口、日期和site标签保留；只补新增的空白测试仪字段。
- 新建FRU填入本板UID派生MAC；不覆盖有效v2或迁移旧记录的MAC。FRU网络字段目前未自动应用到LwIP，不能把持久化配置冒充当前网络状态。
- 旧96字节版本记录只读映射为76字节输出，运行信息仍来源于W25；不从编译期版本替代读取。
- 每个副本先校验CRC和字符串/网络语义，再参与generation选择。更新但字段非法的副本不能掩盖另一份有效数据；更新的已知旧FRU明确触发迁移，不被较旧v2掩盖。
- 校验有效但不认识的schema/size/record格式返回UNSUPPORTED，禁止默认初始化覆盖；写入时也检查两槽，不跨槽容量探测。
- 空白/损坏/已知旧记录仅在首次查询时补写并重读；启动不写生产信息。Boot/factory写入尚未实现，后续替代该临时查询写入流程。

## 启动与内存

1. B1 main保留GPIO安全预置、`pwr_ctrl_init(NULL)`、QSPI初始化、结果灯全灭、UID MAC和PG12 PHY复位。
2. 调度前设置cJSON分配器，创建两条RK业务队列及应用任务，只注册一个RK UART的接收队列。
3. 默认任务在调度后调用`uart_start_all()`：初始化TX锁、挂HAL TXE钩子、开启选中端口RX DMA；随后调用唯一的`MX_LWIP_Init()`。
4. 默认任务推进结果灯和电源状态机；监测和RK发送只在ON状态工作。当前未配置合法上电时序，也未接上电业务，因此默认不访问采样器件或主动发RK帧。

| 区域 | 地址／容量 | 说明 |
|---|---|---|
| FreeRTOS堆 | AXI `0x24000000..0x24020000` | 128KiB，未盲目扩堆 |
| UART DMA | AXI `0x24020000..0x24020840` | 2×1056B缓冲，管理指针仍在启动清零的BSS |
| ETH描述符/接收池 | D2，结束于`0x30004B20` | 不放DTCM、不加DCache维护 |
| LwIP堆预留 | D2 `0x30005000..0x3000D000` | 实际30KiB加元数据预留32KiB；链接器检查不与ETH池重叠 |

UART和DMA中断优先级为5，满足FreeRTOS FromISR边界。NORMAL模式下过滤HT，只按IDLE/TC复制接收块；不把循环DMA模型混入无环形游标的路由器。

RTOS静态预算约92.4KiB用于任务栈、RK消息队列及所选UART接收队列，尚需TCB、锁、cJSON等开销。约35.6KiB预算余量不是实测保证，首板必须读取堆余量和栈水位。编译器报告TCP任务自身栈5520B、RK任务自身栈4408B，仅是局部静态栈，不是完整调用峰值。
