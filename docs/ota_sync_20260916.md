# B1 OTA同步与验证（2026-09-16）

## 已同步

B1接入V2已实测的PC升级链路：0901的begin/write/finish/query/cancel、0902进度、0903健康完成、1024字节Base64块、包头早检/整包校验、重复块只读幂等、断线及30秒空闲取消、提交后约4秒复位。

`App/ota`的安装校验、启动日志、健康观察和下载模块，以及`pc_ota`与V2保持同源内容。信息响应仍从W25持久化记录加载；FRU保留B1旧格式迁移、UID MAC和有效身份不覆盖的规则。健康写日志、查询和下载使用同一Flash事务锁。

## B1差异

- 不移植V2测试任务、灯、GPIO/PHY代码。保留25MHz HSE、400MHz内核、YT PHY、PG12复位、独立MAC、SPI2从机、SPI4采样及PH4/PH5软件I2C。
- 默认电源OFF；只有已健康确认且OFF才接升级。不自动关闭运行中的RK。升级维护占用与上电/调压共用锁，提交后保持到复位。
- 默认、TCP、监测、RK、心跳五个任务参与健康观察。RK在OFF时仍上报任务进展，不等于向未上电RK发送心跳。新增4KiB栈看门狗任务每500ms检查，失败停止喂B已经启动的IWDG。
- B1专用B由独立`bootloader`工程的`BOOT_BOARD=b1`生成。复位入口在RAM初始化/Flash校验之前将PC6/PC7/PG11置低，保留耦合复位语义。B使用HSI，不依赖两板不同HSE。
- MCU的QSPI映射均为PB2/PB6、PF6–PF9，可复用Boot端口；不是RK侧FSPI。B可信板型固定`b1-h743`，与V2的`apollo-v2-h743`互斥，不能混刷。
- 内部B为128KiB；A1=0x08020000、A2=0x08100000，两槽共同镜像上限896KiB。W25沿用版本/FRU双副本、0x4000启动日志、0x10000下载区和0x210000稳定区；不改变FRU地址或擦写它。

复跑时沿用原GNU/CMake/Ninja/Python，在V2目录执行`tests/verify_ota_relocation.py --app-root D:/pro/b1 --app-name b1 --ota-boot --version 0.1.1 --build-type Release`，另传本机`--compiler/--cmake/--ninja`路径；加`--rk-uart 2`验证另一候选串口。仅复用离线工具，不将V2硬件测试放入B1。

独立B构建：在`D:/pro/bootloader`运行`tools/dev.ps1 build -Configuration Release -Board b1`，产物在`build/Release-b1/`。

打包：同目录运行`tools/dev.ps1 ota-pack -Board b1 -AppBuild D:/pro/b1/build/ota-app-0.1.1-release-a1`。包只有一个App及地址修正表，不上传两份App。PC线上接口见[OTA协议](protocol/pc/pc_ota_protocol.md)。

首次部署必须先备份，再准备与B1镜像精确匹配的初始启动记录、版本记录和B1稳定包；B遇到空白/损坏日志留在维护，不猜测有效App。V2维护备份和稳定包不能复制到B1。首次B1部署与B2维护保活协商仍待实板阶段，不在本轮自动执行。
