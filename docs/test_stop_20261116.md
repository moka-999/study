# B1 0104 停止测试

2026-11-16，用户确认收到0104后关闭RK。适用于正式B1，包含TCP8889网络控制台；V2、手动TLV、EDK及服务器文件未改。本次不改变板级电源时序，不自动烧录。

## PC交互

在正式TCP8888发送0104，JSON必须为`{}`，可在启动准备、普通时序发送、FUNC、IDD或SLT执行期间使用，也允许空闲时请求。MCU不额外发accepted；确认停止完成后回复0006：

```json
{"requestCommandId":260,"status":"completed"}
```

网络助手使用HEX发送，例如PC发送Seq=1的完整20字节包：

```text
0000001400010008000001040000000100007B7D
```

- 中止当前执行并丢弃未交付结果，不生成0105/0109默认PASS。已经发给PC的结果不撤回。
- 先停止继续投递，再沿原电源驱动下电。正常ON状态保留反序轨间延时；未完成上电时沿用驱动原有的中断上电关断行为。
- 不等待RK取消或IDD退出回应，不等待EDK RELEASE；正在发送的串口数据须排空。SLT网络恢复、串口115200及解析器复位后，RK任务独自清理请求/结果队列，才允许completed。
- 同一连接的0106整轮保留，灯态仍由0107汇总；收到completed后可直接下发下一项，无需重新0106。RK已经OFF，下一项应携带完整power/bootMode启动配置。
- 停止途中重复0104或新算法回busy；心跳和查询继续。原未完成的启动/电源操作被取代，不再补旧completed；控制台电源请求收到cancelled。
- 驱动失败或OFF后3秒仍未完成串口/网络清理，回复failed及错误码，保持占用，不伪造成功。可再次0104重试；硬件故障仍需处理真实原因。
- 连接断开不取消停止，不向新连接补响应；0106轮次按原断线规则结束。completed不代表PASS，也不证明SLT XML/HTML上传完成，强制下电可能中断报告。

## 实现归属

- `App/protocol/pc/pc_dispatch.c`：校验空对象、撤销旧电源响应归属。
- `App/protocol/pc/pc_test_service.c`：保存停止归属、清理门禁、最终0006，不修改整轮和结果灯。
- `App/protocol/pc/pc_power_service.c`：将原启动/重启替换为OFF，已在下电时只等现有轨间延时。
- `App/tasks/rk/rk_task_control.h`与`rk_task.c`：跨任务停止标记；实际队列、IDD和TLV清理仍在唯一RK任务。
