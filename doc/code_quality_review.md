# 自定义代码规范与结构检查（2026-08-31）

## 本轮结论与范围

已检查自定义层的目录依赖，以及PC通信、RK任务、UART适配、电源监测和Flash信息查询的关键调用链；对明确的边界泄漏、误导注释和适配入口做了小步整理。不是全仓逐行形式化审计，也不是“所有风险已清零”。

本轮只修改V2工程。保留原工作区已有的PC查表分发、详细协议文档和其他未提交修改；未修改CubeMX生成目录、第三方源码、引脚、时钟、PC/RK帧格式、重传参数及W25Q256记录布局。没有烧录、联网或真板采集，没有提交或推送，独立B1工程尚未同步本轮修改。

高内聚的判断标准是“同一模块管理同一类状态和生命周期”，不是把一条调用链全部塞进一个文件。当前PC三层已有明确职责，本轮保留；RK pending只有一个任务使用，未再拆出通用管理框架。

## 已落实的修改

1. 统一自定义代码的I2C/SPI/UART实例声明，删除调用方散落的手写extern；实现自己的头文件优先纳入编译检查。
2. 将UART内部入口移到`uart_hw.h`；`hal_if.h`不再暴露STM32 UART类型。PC协议头仅前向声明cJSON对象，不要求纯帧调用者包含第三方JSON头。
3. RK命令和心跳统一调用`rk_link_next_sequence()`。计数器私有化，64位递增在临界区内；删除无使用者的pending计数，队列使用真实`QueueHandle_t`声明。
4. I2C/SPI适配函数使用明确命名与超时常量，补空指针、空句柄、长度及7位地址边界检查。单寄存器读和Send Byte复用现有事务入口，合法事务格式不变。
5. 监测任务不再读取`.pac_ready/.adc_ready`决定初始化；由组合层的幂等初始化接口只重试未就绪器件。
6. 补充中文注释：缓冲区归属、调用上下文、同步等待、数值单位、部分有效数据和失败策略。修正“UART完全非阻塞”“历史RK队列等于当前PC网关”“B1硬件I2C4”等误导说法。
7. `tools/dev.ps1`增加`style-test`并保留UTF-8 BOM：本机Windows PowerShell 5读取无BOM的中文脚本时，曾发生注释后的语句未执行；编码修正后脚本和头文件检查通过。
8. UART槽位管理状态与DMA载荷分离：前者在`.bss`启动清零，后者保留`.uart_dma`。该DMA段是NOLOAD，新增的注册/空句柄检查不能依赖它上电为零。

### 两处UART修复不是纯风格变化

- 原`uart_tx_mutex_init()`没有调用者，发送函数允许无锁写TX环。现在在`uart_start_all()`中初始化；分配失败时明确拒绝发送，不降级为无锁操作。
- 原实现只根据复制前的“环为空”快照开启TXE。若ISR在检查后排空旧数据并关TXE，新数据可能滞留。现在每次复制后都开启TXE，并在修改中断使能位时恢复进入前的PRIMASK。

这两项已通过编译和策略模型检查，但尚未在V2运行并发压力测试。新增两个TX互斥锁会使用FreeRTOS堆；需要实测堆余量、失败返回和长时间发送稳定性，不能用旧压测成绩替代。

## 后续代码与注释约定

- 自定义C采用4空格缩进；函数左花括号换行，控制语句左花括号同行；新改动的多行分支使用花括号。已有文件按功能块渐进统一，不为改缩进制造全仓噪声。
- 函数/变量用有业务含义的`snake_case`；文件私有状态使用`static`和`s_`前缀；宏/枚举常量大写并带模块前缀。保留HAL/FreeRTOS回调和已发布API名，不为外观批量改名。旧RK的前导下划线私有名仍属待渐进整理项。
- 公共函数在头文件说明输入/输出、单位、返回值及失败后状态；实现旁解释“为什么这样做”和硬件约束，不逐句翻译赋值语句。
- 共享状态由一个模块拥有，外部通过API访问；外部符号在所属头文件声明，禁止在调用方用`extern void *`绕过类型检查。
- 接口写明是否复制/借用缓冲、是否阻塞、能否从ISR调用。`IF_OK`不得被解释为“PC已收到”“芯片已完成测试”或“实际电压已稳定”。
- 数值区分毫秒/RTOS tick、mV/mA/µΩ、7位地址/左移后的HAL地址；寄存器可写范围不等于器件安全工作范围。
- 队列满、总线失败和锁分配失败必须有明确策略。丢弃返回值只在已注明可丢弃或上层恢复策略时使用；不能借“风格整理”掩盖未闭环错误路径。
- 信息响应每次经加载接口读W25Q256。Boot尚未承担写入前保留App的首次初始化兼容路径；本轮未改此生命周期。
- 生成代码和第三方不批量格式化；`.ps1`含中文时保持UTF-8 BOM，C/Markdown用UTF-8。不要在同一功能改动中全仓改换行符。
