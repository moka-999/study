# OTA 3000字节分块修改与实板验证

日期：2026-09-17。V2已完成真实TCP的0.1.4→0.1.5→0.1.6升级，最终运行A2的0.1.6且健康确认；A1保留0.1.5。B1代码和协议同步，构建/离线验证通过，未操作B1硬件。本次未修改飞书；板上原始数据备份保留在本机，不纳入源码仓库。

## 修改范围

- `ota_app.h`统一定义`OTA_DOWNLOAD_BLOCK_BYTES=3000`；下载范围检查、PC解码缓冲和begin返回的blockSize共同使用该常量。
- Base64最长4000字符。18字节头、JSON字段及数据合计仍≤4096；紧凑JSON在最长合法文件偏移下为4086字节。编译期另按最长u32偏移校验预算，线上实际长度仍由公共帧状态机限制。
- PC按begin公布的blockSize分块，不把3000当作3072，不额外转义Base64字符，发送前检查实际UTF-8总长度；较小块合法，末块不补零。
- 不改变`.ota`格式、2MiB下载区、896KiB App上限、Boot安装器、OFF维护门、启动日志或健康/回退策略。未修改TCP任务业务分工；新增/修改注释为中文。
