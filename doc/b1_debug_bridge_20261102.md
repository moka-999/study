# B1 双向RK调试控制台（2026-11-02）

用户确认：USART1输入在RK模式经USART2发送至RK DEBUG；UART4继续独立执行算法协议。保留MCU本地命令和运行时切换，不新增RTOS任务，不修改PC JSON。

## 使用

1. 串口助手使用115200/8N1、无流控，输入`log rk`并换行。
2. 收到`[log] source=rk`后，普通输入及控制字符发送至RK；RK必须自行启用串口控制台。Ctrl+C需实际发送字节`03`，不是文本“Ctrl+C”。
3. 在新行输入`log mcu`并换行返回MCU，再用`status`查询板级状态。RK模式的`status`属于RK输入。

本地切换支持CR、LF、CRLF，切换行不发送至RK。仅行首完整`log mcu`为保留行；前缀暂存直到失配或换行，前缀内退格可编辑，Ctrl+C取消前缀并转发。其他输入按原始字节转发，不统一改换行，不向电脑额外回显。

## 实现

- `../b1/Core/Src/log_console.c`：默认任务内按当前模式处理输入；RK方向新增一块有界暂存，TX环满则保留并在下一轮重试，不重复已接纳字符；同时持续读取RK日志。
- `../b1/HAL_Drv/uart_hw.c`：USART2独立2048字节TX环/锁和HAL TxISR，两个调试端口均0等待取锁；UART4保持原协议发送策略。
- `../b1/Core/Src/main.c`、`b1.ioc`：USART2改为TX_RX；沿用PD5/PD6、DMA1 Stream1接收、现有USART2中断。
- 接收丢块/断流会发本地警告并丢弃到下一个换行，不把残缺后缀当新命令；已经发出的前缀无法撤回。无硬件流控，持续大流量仍可能丢失，不能当作可靠文件传输通道。
