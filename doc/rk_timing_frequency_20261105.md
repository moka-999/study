# MCU–RK 时序与启动频率接入（2026-11-05）

## 本轮确认与证据边界

用户确认：PC判定时序参数的单位、取值及适用性；MCU只校验格式、编码位宽并原值发送。普通时序在重启后进入SPL时设置，不为设置再重启；Freq在启动早期响应RK的Query_Freq。RK稍后补设置成功回应，本轮按**无应答设置**推进，不等待、不臆造成功ACK。

用户随后确认已验证拉偏目标电压下直接正常启动。现有B1流程先缓存本轮训练目标，TPS可访问后首次写入该目标，沿用此启动方式；本轮协议修改不增加先写标称再运行拉偏的步骤。该反馈确认已测试条件下能够启动，不扩展为任意电压组合或全部时序参数已通过验证；也不表示电源上升瞬间已达到软件目标。

服务器只读核查依据为[11月5日记录](rk_protocol_review_20261105.md)和`build/rk_review_20261105/server/`下的部分源码快照；没有修改服务器、构建RK或证明当前板上镜像与源码一致。该目录不是完整工程。

## PC字段与编码

FUNC 0103、PARA 0108、SLT 010A均须有`TimingParameters`对象，默认可用`{}`。以下16项均为可选字符串；空串/省略不继承上次请求。未知、重复、旧字段及非字符串拒绝整包。

| JSON字段 | RK命令 | 线上值 |
|---|---|---|
| Freq | 0x35查询的回复 | 801C，int64LE |
| CASWriteLatency | 0x25 | 701B，u32LE |
| CASReadLatency | 0x26 | 同上 |
| tREFI | 0x28 | 同上 |
| tWR | 0x29 | 同上 |
| tRTP | 0x2A | 同上 |
| tRCD | 0x2B | 同上 |
| tRP | 0x2C | 同上 |
| tRASmin | 0x2D | 同上 |
| tRASmax | 0x2E | 同上 |
| tWTR | 0x2F | 同上 |
| tRFCmin | 0x30 | 同上 |
| tFAW | 0x31 | 同上 |
| tCCD | 0x32 | 同上 |
| tRRD | 0x33 | 同上 |
| BL | 0x34 | 同上 |

- 非空字符串必须是十进制整数；Freq允许负号及完整int64范围，其余允许0..UINT32_MAX。不接收小数、指数、空白、十六进制或单位后缀，不取整、不换算单位、不夹紧数值。
- Freq空串/省略在启动查询中回复-1；RK以负数保留默认频率。PC提供的其他负数仍按原值编码。
- 普通时序空串/省略不发送该项；不重启时，这不保证RK寄存器恢复默认。`"0"`是真正发送0，区别于空串。
- 删除旧`CASLatency/tRC/ODT/tRAS/tRFC/BurstLength`，使用新字段后重新计算PC PDU Length。
- 原三轨电压的TPS编码范围、步进和既有解析规则不变，本轮不修改电源驱动。

## 执行顺序

1. 整包校验、组出受理响应、复制JSON及数值，再受理电源或发送事务；失败不覆盖上一份RAM副本。
2. 完整启动按现有流程准备Boot、训练电压和上电。仅Freq目标变化增加既有冷启动条件；相同Freq、相同电源/Boot、已就绪且`reboot:false`可复用启动。普通时序变化本身不强制重启。
3. RK启动早期发单个`5000(0x35:u16LE)`；MCU立即回复`5001(0x35:u16LE) + 801C(Freq:int64LE)`，整帧34字节。回复使用MCU递增Seq，不套算法结果窗口。B1在WAIT_FIRST_RAIL/WAIT_SECOND_RAIL开放此查询，其余心跳/结果仍须ON；OFF、下电及FAULT仍丢弃RX。
4. FUNC/PARA等待现有本轮普通心跳就绪后，按命令号顺序逐项发`5000(cmd:u16LE) + 701B(value:u32LE)`，整帧30字节。一项一个请求，只接收RK任务的本地SENT事件；发送间隔至少20ms，为当前RK的5ms轮询和主循环留处理时间。该间隔不是RK处理完成的证明。
5. 普通时序发完，再开启B1算法采样统计并投递原FUNC/PARA编号。不自动重发、回滚参数或再次重启。UART整帧入队失败回txFailed并停止后续项/算法；SENT不是RK收到或应用成功的ACK。RK旧设置进度/错误算法回包不会进入当前算法结果。

Freq非负且本轮确实启动时，必须观察到本轮查询回复成功入UART，不能仅凭普通心跳宣称已经回复Freq。额外启动等待上限60秒；没收到查询报timeout，回复发送失败报txFailed，不投递算法，并使启动复用缓存失效。RK没有频率生效ACK，因此发送成功仍不证明训练频率正确。

外部已启动模式保留原电源/Boot不动的约定，可主动发送普通时序；非负Freq回invalidState，因为该模式不重新进入DDR初始化。没有绑定启动请求时，独立查询回复-1，不使用上一请求的频率。

SLT默认空时序保持原有电源/Boot准备，不等待RK。非负Freq须等待本轮查询回复；存在普通时序则另等本轮SPL普通心跳，再逐项发送。010A completed表示本地准备/发送完成，不是SLT完成或寄存器生效；MCU不下发memtest86算法、不检查EDK。若完成上电后的配置失败，保留SLT占用直到原连接010B确认实际结束；断线不自动认领或释放。

V2电源模拟仍不复位真实RK；指定Freq时须由真实RK启动并发查询/心跳，不能用模拟电源状态冒充该交互。B1禁止模拟。
