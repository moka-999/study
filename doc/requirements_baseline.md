# MCU 需求基线（暂定）

- 状态：需求梳理中，不作为最终多方协议批准
- 更新：2026-08-24
- 当前验证平台：阿波罗 V2 + 逻辑分析仪，无 TPS62868/PAC1934/AD7124/MCP4725 外接模块

## 1. 已确认的产品边界

- 每块 B1 是独立测试单元：STM32H743 + RK3588 + LPDDR4/4X；每块 B1 有独立 IP。
- B2 是 8 槽底板，并有一颗由其他同事负责的 B2 MCU；PC按各 B1 的 IP 建立连接。
- MCU负责带外管理和 PC↔RK 网关，不执行内存测试算法本身。
- B1 MCU 通过 SPI2 与 B2 MCU 通信；B2使用一组共享SPI主机总线（SCK/MOSI/MISO）和8个独立CS选择8块B1，每块B1都是SPI2从机。
- B2 MCU 统一负责全部加热逻辑及后续可能增加的底板级控制，并由B2轮询各B1从机、仲裁资源；B1只提出请求和返回本槽状态。
- PC–MCU 与 MCU–RK 复用同一底层 TLV 帧格式，但业务命令空间分开定义。
- PC–B1 MCU、B1 MCU–RK、B1 MCU–B2 MCU 的业务命令及转换关系纳入后续共享协议规范；当前“响应同 CmdID”仅是回归基线。
- 初版不实现 OTA；只保留 W25Q256 驱动、固件版本信息和不阻塞后续 OTA 的启动布局。
- RK 的 Boot 模式由 MCP4725 设置；RK 重启走 MCU 电源控制形成硬断电复位，不使用 PG12 直拉复位脚。
- PAC1934 确认会安装在实际电路板上，属于初版电流采样路径。
- CPU 温度、CPU 电压和风扇状态由 RK 采集，再经 MCU–RK 业务协议提供给 MCU/PC。
- 初版验证目标是 V2 模拟验证，不宣称最终外设或 B1/B2 真板验证。
- Apollo V2与B1使用不同MAC：V2保持历史固定MAC；B1当前按STM32 UID生成稳定的本地管理单播MAC，量产分配规则可在FRU定义后替换。
- 以太网PHY型号不同：Apollo V2官方IO表确认为YT8512C，B1最新原理图P23为YT8512H；两者共用当前Clause 22链路驱动，但PHY复位路径必须分板型实现。

## 3. 明确不在初版范围

- OTA下载协议、镜像分区/切换、W25Q→内部Flash搬移、自动回滚。
- 最终电压/电流精度、量程、温漂和电源时序标定。
- 460800/921600 高波特率和最终 RS0102 UART 联调。
- B1 MCU的加热控制；全部加热逻辑归B2 MCU，B2 MCU固件由其他同事负责。
- SPD Preload/override；该需求已取消。

## 4. 原理图核对结论

依据 `docs/MYZR-RK3588-ZUOYI_SCH_20260811.pdf`：

| 能力 | 原理图证据 | 需求判断 |
|---|---|---|
| MCU结果灯 | PG0–PG6 → 2N7002；LED1/2、3/4、5/6组成三颗红绿双色灯，LED7驱动单色LED4；另有`CPU_GPIO_PWR`驱动单色LED5 | 三颗双色灯分别监控两组LPDDR4/4X和一组eMCP；两颗单色灯用于板卡/上电状态，精确语义待定 |
| W25Q256 | U2接 MCU QSPI | 支持固件/数据存储；器件是 NOR Flash，图中“SPI NAND FLASH”标题不准确 |
| DDR电源 | PC7控制3.3V、PC6控制4.0V、PG11统一使能三颗TPS62868 | 与电源管理职责一致；精确时序需真板测量 |
| 整机开机 | ATX开启后B2 standby/LAN Switch先上电；随后可按面板PWR键手动启动site，也可由上位机经B2 standby远程启动site | 两种入口与PC6/PC7/PG11板内时序分层；当前24页图没有STM32 GPIO到site PWR的控制路径，远程入口属于B2 standby或未提供图纸 |
| TPS62868/69 VSET | U4025=TPS628692A+56.2kΩ；U4026=TPS628681A+86.8kΩ；U4027=TPS628681A+15.4kΩ | 因子依次2/1/1；地址0x49/0x41/0x4F；启动电压1.60/0.90/0.50V |
| 电压采样 | AD7124通过SPI4接三路DDR电压 | 与三轨电压回读一致 |
| 电流采样 | PAC1934挂I2C4并采样三路；图纸虽然标注可移除，项目已确认实际板安装 | 属于初版必需功能，真板到货后验证 |
| RK通信 | UART4、USART2经RS0102；USART1是本地串口 | 最终端口不能继续使用当前USART1配置 |
| Boot模式 | MCP4725挂I2C2，输出到BOOT_SARADC_IN0；P24 Table 1给出0/0.3/0.6/0.9/1.2/1.5/1.8V模式表 | 模式与目标电压已确定；DAC码可按3.3V计算，实际输出只需真板校准 |
| RK复位 | P18: PC6使能MP8759生成`VCC4V0_SYS`；P12: 该电源给RK806 PMIC供电。P17: PC7控制系统3.3V；P22: PG11控制DDR三轨 | 通过`pwr_ctrl`关闭/开启RK供电实现硬复位；PC7/PC6/PG11顺序和延时待真板验证 |
| RK PWRON_L | P24仅画出`PWRON_L`经R303接按键SW9到GND，未见MCU GPIO驱动 | 当前不能当作MCU可控信号；是否需要按键模拟待真板联调 |
| PHY复位 | P21的PG12连接`ETH_nRST`，经ETH切换器到B1/B2 PHY | B1必须用PG12复位PHY；PA0是WK-UP，不能沿用旧引脚表 |
| PHY型号 | B1 P23标注YT8512H；Apollo V2 IO分配表标注YT8512C | 不是LAN8720/YT8512的区别；两板都是YT8512系列，但型号和复位布线不同 |
| CPU温度/风扇 | 未发现MCU直连温度或风扇测速信号；风扇由RK PWM控制 | 确认由RK采集，并通过MCU–RK协议上报 |
| FRU信息 | 无独立FRU EEPROM，W25Q256由B1 MCU管理 | FRU确定存入W25Q256；数据结构和更新策略待定义 |
| B1–B2 MCU SPI | STM32 SPI2的PB12–PB15以`MCU_SPI_NCS/CLK/MISO/MOSI`引出；B2共享时钟/数据线并以8个CS分别选中8块B1 | B2主/B1从；Mode 0、8位MSB、硬件NSS低有效，B2初始1MHz；其余协议待双方定义 |

## 5. 当前冲突与待确认项

1. 三颗双色灯确定对应两组LPDDR4/4X和一组eMCP，但物理灯号顺序待填；两颗单色灯的上电/状态语义待定。
2. 整机有“面板PWR键手动开机”和“上位机经B2 standby远程开机”两种入口；当前B1/MB360图中`PWRON_L`只接人工按键，未找到B1 MCU控制GPIO。B2 standby如何驱动site PWR、反馈结果及处理重复命令仍待B2接口/图纸确认。
3. RK硬复位应迁移到`pwr_ctrl`电源循环；PC6/PC7顺序必须按RK3588/RK806和原理图要求实现，PG11使能TPS62868后再通过I2C配置LPDDR三轨；精确延时待真板验证。
4. TPS料号已确认为U4025=TPS628692A、U4026/U4027=TPS628681A；地址按0x49/0x41/0x4F实现。U4026的86.8kΩ按TI标称86.6kΩ档处理。
5. B1–B2 MCU SPI已定为B2共享总线主机、B1 SPI2从机；Mode 0、8位MSB、硬件NSS低有效和B2初始1MHz作为联调基线。固定邮箱/帧长、精确轮询周期、帧映射、超时安全策略、重试/幂等、启动握手和业务命令集待B2 MCU负责人共同定义。
6. PC–B1 MCU、B1 MCU–RK业务协议和转换规则由PC/B1 MCU/RK评审决定；在此之前只维护公共帧层和现有回归行为。
7. FRU字段、双副本/CRC及生产写入流程待定义；B1 IP配置方式、异常安全策略待定。

## 6. LED状态定义

三颗双色结果灯统一采用以下状态机：

| LED状态 | 业务含义 | 治具/安全要求 |
|---|---|---|
| 红色常亮 | 测试结果 FAIL | 可以打开治具并取出芯片 |
| 绿色常亮 | 测试结果 PASS | 可以打开治具并取出芯片 |
| 橙色闪烁 | 常温测试进行中 | 禁止打开治具 |
| 红色闪烁 | 高温测试进行中 | 禁止触碰治具，防止烫伤 |

三颗双色灯分别服务于LPDDR4/4X通道0、LPDDR4/4X通道1和eMCP；具体物理灯号顺序放在板级配置中。所有闪烁状态统一为亮500ms、灭500ms（完整周期1秒，占空比50%）。

另外两颗单色灯：LED4由B1 MCU的`LED7/PG6`控制，LED5由`CPU_GPIO_PWR`控制。它们暂按板卡/上电状态灯管理，具体“正常、待机、故障”的亮灭规则待定，不能占用测试结果语义。

软件接口暂定为：

- `result_led_set(index, FAIL/PASS/TEST_NORMAL/TEST_HOT/OFF)`：驱动内部转换为红、绿、橙及闪烁组合。
- `board_status_led_set(state)`：只控制B1 MCU可控的LED4；状态枚举待单色灯语义冻结。
- `CPU_GPIO_PWR`对应LED5不由B1 MCU结果灯驱动控制。

阿波罗 V2 使用替代 GPIO 观察波形；最终 B1 映射为 PG0–PG6，且与当前 PB0/PB1、低有效的开发板 LED 驱动不是同一套电气模型。
