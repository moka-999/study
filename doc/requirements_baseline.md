## 1. 已确认的产品边界

- 每块 B1 是独立测试单元：STM32H743 + RK3588 + LPDDR4/4X；每块 B1 有独立 IP。
- B2 是 8 槽底板，并有一颗由其他同事负责的 B2 MCU；PC按各 B1 的 IP 建立连接。
- 正式B1的IP由B2 MCU告知，不以B1本地固定地址或FRU中的配置IP作为正式地址来源。2026-09-30进一步确认PC配置B2、B2经SPI通知8块B1，地址按下方§1.1计算；当前测试继续使用本地配置`192.168.1.201:8888`。本次只记录，不修改网络代码、SPI报文或W25Q256的FRU布局。
- 整机与槽位的地址编号以§1.1为准，替代早期未冻结的地址示例；物理片选与槽位号的对应关系仍待确认。0821评审截图中的PB3/PB4/PB5只明确提出在位检测，不能直接认定为已落实的槽位码；ETH1/PHY侧切换及FX18默认路径须以整改后原理图确认。本次不更改GPIO或网络切换行为。
- MCU负责带外管理和 PC↔RK 网关，不执行内存测试算法本身。
- B1 MCU通过SPI2与B2 MCU保活，并按2026-09-30确认的需求接收网络配置通知（通知协议尚未实现）；B2使用一组共享SPI主机总线（SCK/MOSI/MISO）和8个独立CS选择8块B1，每块B1都是SPI2从机。该链路不承载温控或测试业务转发。
- PC通过独立接口直接管理B2 MCU的温控；B2 MCU统一负责全部加热逻辑及其他底板级控制，B1不控制、代理或转发温控。
- PC–B1 MCU与B1 MCU–RK使用两套独立协议：PC–MCU采用固定18字节大端头部和UTF-8 JSON包体；MCU–RK保留0x5A/0xA5框架，但用户于2026-09-23指定以`D:/pro/tlv_proto`替换旧协议，CRC覆盖Seq＋TLV、Value整数小端、最终结果四TLV聚合。正式启动/电源/RK-ready业务不因底层协议替换而自动放行，见[RK协议](protocol_spec.md)。
- B1 MCU负责两套业务协议之间的语义转换，不直接透传对侧原始帧；PC Seq与RK Seq相互独立，MCU在内部维护请求映射。
- PC–MCU固定头字段依次为`Length:u32/Version:u16/Flag:u16/ServiceID:u16/CommandID:u16/Seq:u32/Reserved:u16`。`Length`为完整PDU长度，初版`Version=1`、`Flag=8`；Length字段为u32，MCU完整PDU上限为4096字节。
- MCU仍是TCP:8888单客户端server。PC协议解析必须处理半包、粘包和连续多帧；非法长度、版本或Flag直接关闭连接。测试仪信息查询/响应已冻结为0x0101/0x0102，其余命令枚举和JSON字段分批冻结。
- 测试仪信息不在连接建立后主动发送；PC发送`0x0101+{}`后，MCU返回`0x0102`。`testerName/testerVersion/testBoard`分别从W25Q256 FRU v2的`tester_name/hardware_revision/test_board`读取。
- 2026-08-31协议确认：ServiceID保留2字节但不使用，固定填0；每条连接中PC和MCU分别维护自己的发送Seq，每发一帧本端加1，不再回显请求Seq。接收对方报文不改变本端计数，两个方向允许数值相同且可以同时发送；心跳、应答和上报共用本端计数。Seq仅表示发送顺序，业务关联另行明确。起始值、重连初始化和回绕边界留到实现任务9.6统一，原先写入的“从1开始/重连归1”不作为已批准规则。
- siteId/mirrorIndex继续保留字段及类型，具体含义和编号规则后续规定；测试仪信息当前仅规定基本JSON格式，固件版本等后续信息可追加到0x0102响应，不必新增命令或本轮扩展Flash结构。
- 当前实现使用cJSON v1.7.19、FreeRTOS堆和16层嵌套限制；正式TCP传输入口已切到PC帧/cJSON，本地命令dispatch已接入，PC业务到RK的适配尚未接入。固件仍使用旧版ServiceID/Seq回显，尚未实现上述8月31日修订；内部RK Seq保持独立，详见任务9.6。
- 0x0006为通用命令执行结果，不是错误专用响应；JSON使用`requestCommandId`和`status=accepted|completed|failed`，仅failed携带`errorCode`。0x0509为DDR类型及三轨电压配置入口。Boot设置仅作用于下次启动、不隐含重启；Boot查询返回配置模式，不代表RK实际启动介质。
- PC–B2温控协议由B2工程维护；B1–B2的SPI需求范围为保活和网络配置通知，不承载温控或测试业务转发。
- 既有阶段仅预留W25Q256/版本和启动布局；2026-09-09新增OTA设计范围：内部B/A1/A2、W25Q256下载及稳定版、B安装、版本/CRC校验、3+3失败恢复、30秒健康确认，仅空闲维护升级。初版不做B在线更新、签名或人工降级入口；详见[OTA初版设计](ota_design.md)，本次不代表固件已实现OTA。
- 所有固件/FRU/测试仪等信息类PC响应均以W25Q256持久化记录为唯一运行时数据源。编译期结构只能用于空白Flash初始化、打包和自检，不得直接组成PC响应。
- RK 的 Boot 模式由 MCP4725 设置；RK 重启走 MCU 电源控制形成硬断电复位，不使用 PG12 直拉复位脚。
- PAC1934 确认会安装在实际电路板上，属于初版电流采样路径。
- LPDDR的IDD测试状态（CKE/时钟/命令/数据模式）由RK按照JESD209-4E产生；B1 MCU只负责TPS三轨供电/拉偏和PAC1934三轨采样。正常下电必须先取得RK安全掉电确认。
- 2026-09-14电源需求：开始测试仍为一条指令，`power`表示本次DDR初始化/训练目标电压。电源配置改变时必须受控断电重启，PC检查与MCU判断不一致时以MCU为准；不能实现为训练后才调压。用户接受先按“RK806自动启动窗口足够完成目标写入及稳定”推进软件，此最坏时序尚未验证。V2/B1训练目标底层已实现，业务安全范围/组合校验、配置比较、自动冷重启和RK-ready仍未实现；详见[电源控制记录](b1_power_control_review.md)。同日按用户反馈精简[PC协议4.7节](pc_tcp_protocol_spec.md#47-开始测试0x0103)：以`algorithmType/algorithmName`标识算法，保留`algorithmIndex`标识PC当前计划中的算法项，MCU原样带回供PC对齐结果并推进计划；`power`为内存类型和相对标称值的三路20mV有符号档位，保留`reboot/bootMode`且重启统一受控断电；仅去掉小类和重启类型。结果包同步大类/名称/index。新业务尚未接入固件，不删除已有独立命令，index不等于RK内部算法ID，安全电压表不由文档示例代定。
- CPU 温度、CPU 电压和风扇状态由 RK 采集，再经 MCU–RK 业务协议提供给 MCU/PC。
- 初版验证目标是 V2 模拟验证，不宣称最终外设或 B1/B2 真板验证。
- Apollo V2与B1使用不同MAC：V2保持历史固定MAC；B1当前按STM32 UID生成稳定的本地管理单播MAC，量产分配规则可在FRU定义后替换。
- 以太网PHY型号不同：Apollo V2官方IO表确认为YT8512C，B1最新原理图P23为YT8512H；两者共用当前Clause 22链路驱动，但PHY复位路径必须分板型实现。

## 5. 当前冲突与待确认项

1. 三颗双色灯确定对应两组LPDDR4/4X和一组eMCP，但物理灯号顺序待填；两颗单色灯的上电/状态语义待定。
2. 整机有“面板PWR键手动开机”和“上位机经B2 standby远程开机”两种入口；当前B1/MB360图中`PWRON_L`只接人工按键，未找到B1 MCU控制GPIO。B2 standby如何驱动site PWR、反馈结果及处理重复命令仍待B2接口/图纸确认。
3. RK正常重启走B1受控电源循环。PC6上电后TPS与RK806同时启动，PG11的NC连接不能提供独立时序控制；训练目标写入、模拟电压稳定、RK复位/DDR初始化及失败撤销须证明满足最坏时序，详见电源控制记录。

## 6. LED状态定义

三颗双色结果灯统一采用以下状态机：

| LED状态 | 业务含义 | 治具/安全要求 |
|---|---|---|
| 红色常亮 | 测试结果 FAIL | 可以打开治具并取出芯片 |
| 绿色常亮 | 测试结果 PASS | 可以打开治具并取出芯片 |
| 橙色闪烁 | 常温测试进行中 | 禁止打开治具 |
| 红色闪烁 | 高温测试进行中 | 禁止触碰治具，防止烫伤 |

三颗双色灯分别服务于LPDDR4/4X通道0、LPDDR4/4X通道1和eMCP；具体物理灯号顺序放在板级配置中。所有闪烁状态统一为亮500ms、灭500ms（完整周期1秒，占空比50%）。

另外两颗单色灯：LED4由B1 MCU的`LED7/PG6`控制，LED5由`CPU_GPIO_PWR`控制。它们暂按板卡/上电状态灯管理，具体“正常、待机、故障”的亮灭规则待定，不能占用测试结果语义。

软件接口暂定为：

- `result_led_set(index, FAIL/PASS/TEST_NORMAL/TEST_HOT/OFF)`：驱动内部转换为红、绿、橙及闪烁组合。
- `board_status_led_set(state)`：只控制B1 MCU可控的LED4；状态枚举待单色灯语义冻结。
- `CPU_GPIO_PWR`对应LED5不由B1 MCU结果灯驱动控制。

阿波罗 V2 使用替代 GPIO 观察波形；最终 B1 映射为 PG0–PG6，且与当前 PB0/PB1、低有效的开发板 LED 驱动不是同一套电气模型。
