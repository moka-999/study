# B1–B2 SPI通信协议

版本：v0.1，2026-10-19。供B1/B2双方评审；本稿不代表固件已接入或硬件已验收。

## 1. 范围与接口

初版只传保活、测试仪编号、加热状态及测试中灯态。不传测试算法、测量数据、OTA文件或加热控制命令。PC直接管理B2加热，直接连接B1执行测试。

| 项目 | 约定 |
|---|---|
| 主从 | B2为主机，8块B1各为SPI2从机 |
| 总线 | SCK/MOSI/MISO共享，每块B1独立CS；同时只选中一块 |
| 参数 | Mode 0，8位，MSB优先，CS低有效，初始SCK 1MHz |
| B1引脚 | PB12=CS，PB13=SCK，PB14=MISO，PB15=MOSI |
| 事务大小 | 每次CS拉低传输64字节，传完拉高；一事务最多一帧 |
| 填充 | 有效帧从第0字节开始，帧尾之后填0xFF；填充不参与CRC |
| 未选中 | B1不得驱动共享MISO；B2切换片选时先释放前一槽 |
| 编号 | testerId=整机编号1～21；siteId=GPIO原始槽位码+1，范围1～8 |

PB3为槽位码最低位。B2贴装与物理槽位必须符合000→1、001→2、…、111→8；siteId与DDR的mirrorIndex无关。八槽贴装及CS对应需实物核对。

## 2. 一次请求与应答

1. B2写请求：选中B1，MOSI发送完整帧并补0xFF至64字节。此时MISO内容不作为本次应答。
2. B1在写事务结束时使旧应答失效；完整校验后处理请求，准备本次应答。
3. B2等5ms后读应答：再次选中同一B1，MOSI发送64个0xFF，读取MISO的64字节。
4. 全0xFF表示应答未就绪；其他无效数据也不算应答。B2每隔5ms继续读取，直到收到匹配帧或超时。
5. 应答准备好后保留到下一次写请求；重复读取不重复执行业务。B1只在CS为高时发布发送缓冲，单次64字节读事务内内容不得变化。

读应答的全0xFF不是命令，不清除应答，不刷新B1侧保活。短事务、超长事务或未对齐的帧整事务丢弃，不在数据内部搜索新的帧头。B1复位或未准备好时，B2不得把浮空数据当作有效回复。

| 项目 | 初版联调值 |
|---|---|
| 两次CS之间高电平间隔 | 不小于1ms |
| 首次读及后续读间隔 | 5ms |
| 单次请求等待上限 | 从写事务结束起100ms |
| 重发 | 最多2次；使用同一Seq和相同请求内容 |
| 保活/状态更新 | 每槽目标周期1秒；B2等待某槽时可访问其他槽 |
| 通信失联 | 3秒没有有效请求/匹配回复则标记失联，不自动复位或断电 |

每个B1同时只处理一个请求；不同槽可独立等待。重试耗尽只表示结果未确认，不等于请求一定未执行，随后通过保活查询当前生效编号。

Seq由B2对每槽独立分配，首次为1，新请求加1，u64回绕后为0；B1应答回显本次Seq。B2同时核对CS、Seq及应答命令号。B1不采用RK的“最近Seq窗口”，也不把Seq当成测试计划号或持久化去重标志。B2重启可重置序号，但必须先写请求，不能直接认领旧应答。三条命令均采用幂等查询/状态赋值，重复请求不得导致重复改IP、重启或写Flash。

## 3. 帧格式

复用RK的线格式和CRC算法；本SPI业务编号独立，不交给RK任务处理。

| 字段 | 偏移 | 长度 | 规则 |
|---|---:|---:|---|
| Header | 0 | 1 | 0x5A |
| Length | 1 | 2 | 大端，TLV区总长度N，含各TLV头；本协议6≤N≤48 |
| HCRC | 3 | 2 | 小端，对偏移0～2共3字节计算CRC |
| Seq | 5 | 8 | 大端，B2请求序号；B1原样回显 |
| TLV | 13 | N | Type:u16大端、ValueLength:u16大端、Value |
| FCRC | 13+N | 2 | 小端，只覆盖Seq与TLV，共8+N字节 |
| Footer | 15+N | 1 | 0xA5 |

有效帧长为16+N，最多64字节。CRC为Modbus CRC-16：初值0xFFFF，右移多项式0xA001，无最终异或。Value内多字节整数采用小端。SPI硬件CRC关闭。

| TLV Type | 字段 | Value长度 | Value说明 |
|---|---|---:|---|
| 0x5000 | commandId | 2 | 请求命令号，u16小端 |
| 0x5001 | requestCommandId | 2 | 应答对应的命令号，u16小端 |
| 0x3002 | status | 1 | 执行结果，见下表 |
| 0x3003 | testerId | 1 | 请求仅1～21；应答0表示尚未配置 |
| 0x3004 | siteId | 1 | 当前B1槽位编号1～8 |
| 0x1005 | heating | 1 | 0=未加热，1=正在加热；由B2提供，仅记录，不控制输出 |
| 0x0006 | ledStates | 3 | 依次为镜像0、1、2对应的测试中灯态 |

每个指定字段恰好一次，按命令表所列顺序排列；重复、缺失、未知字段或长度不符拒绝。仅允许一条请求命令。坏帧头/长度/CRC/帧尾不执行、不回复；能够识别命令且结构完整的业务参数错误回复非零status。

## 4. 三条基本命令

| commandId | 名称 | B2请求TLV | B1处理 |
|---|---|---|---|
| 0x0001 | 保活/基本状态查询 | 5000=0001 | 不改变业务状态，回复当前testerId和siteId |
| 0x0002 | 设置测试仪编号 | 5000=0002、3003=testerId | 计算并应用本B1的正式IP；编号只有1字节 |
| 0x0003 | 更新测试中状态 | 5000=0003、1005=heating、0006=ledStates | 当前整轮中记录加热状态，原子更新三盏灯；不操作加热、电源或RK |

所有应答均依次携带：5001=requestCommandId、3002=status、3003=当前生效testerId、3004=siteId。应答有效帧固定37字节，其余27字节填0xFF。

| status | 含义 |
|---:|---|
| 0 | 成功；设置编号时表示软件网络配置已应用，不代表网线或PC已连通 |
| 1 | 参数、字段或取值不合法 |
| 2 | 当前忙，不允许修改 |
| 3 | 命令不支持 |
| 4 | 执行失败 |
| 5 | 当前没有0106建立的有效整轮 |

### 4.1 编号与IP

```text
T = B2下发的testerId（1～21）
S = GPIO槽位码 + 1（1～8）
B1 IP = 192.168.210.(10*T + S)
B2 IP = 192.168.210.(10*T)
PC IP = 192.168.210.9
B1 TCP端口 = 8888
```

例：testerId=3、槽位码=2，则siteId=3、B1 IP=192.168.210.33。PC JSON仍以字符串上报siteId，例如"3"；同一siteId可在不同整机重复。

- 本稿采用每次B1启动等待B2重新下发编号、不写W25的方式。未配置时testerId=0，不启用共享的默认测试IP，不接受正式PC业务。
- 重复下发已生效的相同编号直接成功，不重建连接。
- 修改为不同编号仅在没有PC客户端、整轮/算法/SLT、电源操作及OTA写事务时接受；拒绝时保留旧编号和网络配置。
- 编号、siteId及IP按一次配置生效；更改IP不复位MCU/RK、不改电源。网络更新失败不得返回成功。
- 掩码与网关由双方事先固定，不在SPI逐次下发；其生产值仍需确认，不从IP前缀擅自推定。

### 4.2 测试期间的灯态

| ledStates单字节值 | 显示 |
|---:|---|
| 0 | 熄灭 |
| 1 | 常温测试闪烁，两通道同时亮/灭各500ms |
| 2 | 高温警示闪烁，FAIL通道亮/灭各500ms |

B2只提供测试中状态，不提供PASS/FAIL结论。0107仍按PC失败清单生成最终灯态；0107之后拒绝0x0003，不允许迟到的测试中状态覆盖终态。下一次0106才重新允许更新。

B2应发送当前状态，不排队补发旧测试状态。初版无跨计划标识，不宣称能够识别被重新发送为当前状态的上一轮数据。3秒未收到成功更新则将加热/灯态信息标为失效，不解释为停止加热、已经冷却或PASS，也不自动关电；显示保留最后状态。heating、常温闪或最终PASS均不是可触碰确认，温控与独立安全措施仍由PC/B2负责。

## 5. 完整帧示例

下面只列有效帧，线上每次事务还需补0xFF到64字节。

保活请求，Seq=1（22字节）：

```text
5A 00 06 D1 D1 00 00 00 00 00 00 00 01 50 00 00 02 01 00 17 C1 A5
```

设置testerId=3，Seq=2（27字节）：

```text
5A 00 0B 10 14 00 00 00 00 00 00 00 02 50 00 00 02 02 00 30 03 00 01 03 7F 2A A5
```

对应成功应答，当前siteId=3、testerId=3（37字节）：

```text
5A 00 15 90 1C 00 00 00 00 00 00 00 02 50 01 00 02 02 00 30 02 00 01 00 30 03 00 01 03 30 04 00 01 03 E3 77 A5
```

测试中状态，Seq=3，正在加热，前两灯高温闪、第三灯灭（34字节）：

```text
5A 00 12 D1 DE 00 00 00 00 00 00 00 03 50 00 00 02 03 00 10 05 00 01 01 00 06 00 03 02 02 00 0A 5C A5
```

## 6. 实施前双方确认

双方评审本稿帧/命令及状态规则，尤其确认GPIO贴装/CS与槽位映射、固定掩码和网关、表内SPI时序/超时值、加热及灯态定义。B2首次如何被PC配置属于PC–B2接口。

本稿先采用SPI承载上述三项业务。ETH主用/SPI备用是可选后续方案，不属于已实现功能，也不改变现有PC–B1单客户端TCP协议。
