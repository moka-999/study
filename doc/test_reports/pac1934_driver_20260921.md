# PAC1934驱动修正与最短等待验证

日期：2026-09-21。范围：V2与同级B1的PAC底层、等待回调及故障重初始化。按用户要求，IDD业务窗口、RK配合、约2秒后台采样节奏和测试判限暂不修改。未连接或烧录板卡，未提交/推送。

## 已修正

| 项目 | 修正与边界 |
|---|---|
| 通道关闭映射 | 软件bit0..3表示CH1..4；器件关闭位为bit7..4。启用前三路时写0x10，原0x80会误关CH1。旧Mock也使用了错误期望，不能作为修复前正确性的证据。 |
| 功率数据对齐 | 线上四字节的bit31..4为有效功率码，先右移4位再换算，修复原16倍偏大；低4位非法时拒绝数据。 |
| 配置有效性 | 显式写单极性；初始化核对ACT，每份读数核对ACT与LAT的速率、模式、通道和极性。不把I2C写ACK等同于配置生效。 |
| 失败交付与恢复 | IO、身份、配置及格式异常使句柄失效；组合层下一监测周期重新初始化。单通道/批量输出都仅成功后交付，失败不把半份数据或旧值标成有效。 |
| 量程上沿 | 编码达到满量程上沿，报告疑似饱和并拒绝本次数据，不直接宣判DDR FAIL，也不因此反复初始化。 |
| 低电流信息 | 新增uint64_t current_ua及纯整数µA换算，保留不足1mA的信息；兼容的current_ma仍取整。PC currentMa和现有IDD统计单位暂不改。µA表示单位，不等于1µA测量精度。 |
| 板型参数 | V2为10mΩ；新版B1为20mΩ，仍由各自板级参数配置。引脚、软件I2C和AD分压差异不变。 |

依据：[Microchip PAC1931/2/3/4数据手册DS20005850E](https://ww1.microchip.com/downloads/en/DeviceDoc/PAC1931-Family-Data-Sheet-DS20005850E.pdf)，第18–19、41–43、46–49页。手册要求与测试模型分开：模型只验证代码按这些合同执行，不能证明实物行为。

## wait_ms(1)如何保证

两套工程已经用TIM1产生HAL的1ms时基，FreeRTOS另用SysTick，不新增定时器或中断。新增共用的`HAL_Drv/device_wait.h`：等待期间用vTaskDelay让出CPU，并反复检查HAL时基，直到差值严格大于请求毫秒数，以补偿进入时不足一个tick的相位。0立即返回，长等待分段并处理uint32_t计数回绕。

该函数只允许在调度器运行、TIM1/HAL时基正常、中断开启的任务上下文使用，不能放到ISR、临界区或挂起调度器的路径。提供最短等待，不提供准时唤醒保证：实际可能超过1ms，不用于微秒级波形或RK/DDR同步触发。正式监测任务以及V2 test_task内的AD/PAC等待回调均复用此函数。

初始化等待20ms器件启动、126ms旧采样周期/配置切换，再等新速率的一个周期；普通1024SPS配置的请求等待合计147ms，另有节拍余量、总线和调度时间。这只发生在首次或故障重初始化，不是每次采样延迟，也不是DDR上电时序。每次REFRESH_V后仍只请求至少1ms。

## 已运行的验证

- 两板实际PAC C源码、实际组合层与实际等待函数在ARM/QEMU运行通过：15种通道掩码、4种采样率、功率对齐、10/20mΩ与低电流换算、逐事务IO故障、ACT/LAT不符、保留位/量程异常、输出不变和下一周期恢复。
- 等待函数覆盖进入相位0/1/999µs、TIM1/SysTick同相和半周期偏移、0/1/20/126/1001ms及HAL计数回绕；模型故意允许一次vTaskDelay(1)只经历1µs，仍不能提前交付。
- 两板AD7124、UART/IDD统计、真实monitor任务循环及PC 0103/0602 C回归通过；PC字段/单位未变。
- 两板Debug、V2隔离Mock及V2/B1 UART4/B1 UART2三种OTA槽限Release构建通过。Mock镜像本轮只构建，未烧录执行；不得沿用旧56 PASS作为本轮执行结果。
- 既有PC合同24项、RK模型96项、边界19项/纯头检查、电源/LPDDR/Boot模型和B1完整check通过。这些模型不是网络或电气测试。
