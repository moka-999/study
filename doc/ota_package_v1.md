# 单App升级包与安装核心 v1

更新：2026-09-15。已实现文件工具及C核心，未接真实QSPI/内部Flash驱动或自动启动。
这是MCU内部安装文件格式，不分配PC命令号、不改变18字节TCP头。

## 文件内容

只传一个A1基准App：`40B包头 + 76B既有版本信息 + N×4B地址修正表 + App.bin`。
所有整数小端，文件无额外对齐填充；完整文件长度必须精确相符，不能附加尾数据。
包不携带可随意选择的Flash地址、降级许可或第二份App。

| 包头偏移 | 类型 | 含义/固定值 |
|---|---|---|
| 0 | u32 | `0x3141544F`，字节为`OTA1` |
| 4 | u16 | 文件格式版本，固定1 |
| 6 | u16 | 包头长度，固定40 |
| 8 | u16 | 最低Boot接口版本，当前只接受1；不是App版本号 |
| 10 | u16 | 标志，固定0 |
| 12 | u32 | 整包字节数，最多2MiB |
| 16 | u32 | 地址修正项数量N |
| 20 | u32 | 修正表CRC32 |
| 24 | u32 | A2安装镜像预期CRC32 |
| 28 | u32 | 紧随包头的76B版本载荷CRC32 |
| 32 | u32 | 保留，固定0 |
| 36 | u32 | 包头前36字节的CRC32 |

版本载荷复用`test.version.bin`，不新增一套版本结构：schema/size在0/2，
major/minor/patch在4/6/8，10–11填零，镜像长度/基准CRC在12/16，
构建时间24B在20，build_id 16B在44，target 16B在60。字符串非空、有NUL终止，尾部填零。
`target`必须与可信本机板型匹配；V2为`apollo-v2-h743`。

CRC均沿用现有IEEE CRC32，与`zlib.crc32`一致。头/元数据/表/镜像各自校验覆盖整个文件，
不是数字签名，也不抵御攻击者重新计算CRC。只用于可信固件发布渠道下的完整性检查。

修正偏移相对App起点，不相对文件起点。第一项必须为复位向量偏移4；后续严格递增、
间距至少4，位置和32位值均在基准镜像范围（允许值为一过尾符号）。不要求位置4B对齐。
按ELF记录修正，不扫描“看起来像地址”的常数；未知ELF类型在发布端拒绝。
SP需8B对齐并位于项目RAM白名单，复位入口须为Thumb且至少有完整2B指令空间。

## 工具与调用边界

`tools/pack_ota.py`复用App的`verify_ota_relocation.py`提取器，检查bin与ELF一致、
版本载荷匹配、离线A2/反向验证报告及转换产物一致，再生成`test.ota`。
独立A2构建只用来验证修正结果，不放入下载包。

`boot/ota_install.c/.h`提供两个入口：

- `ota_package_validate()`只读校验，供下载完成及B安装前使用。
- `ota_install()`重新全量校验→可靠标记INSTALLING→擦除目标7扇区→修正/32B写入→内部读回CRC。

当前核心只处理普通升级：可信请求给出已确认槽、当前三段版本、板型、文件长度与头CRC。
包版本必须严格更高；A1确认时写A2，A2确认时写A1。可信请求不能直接取PC自报的当前槽。
文件长度/头CRC与已提交请求绑定；同一安装失败重试必须沿用该请求，不能把半成品当成当前槽。
稳定版恢复的受控降级和固定A1目标尚未接入，不能用包标志自行绕过这些限制。

读源仅限W25下载区`0x10000..0x20FFFF`，没有外部写回操作。内部只擦目标共同容量896KiB，
B、当前可用App和A2尾部128KiB不擦写。256B流式缓冲保留3B前瞻，支持修正项跨32B/256B边界；
最后一个Flash-word补FF，镜像CRC不计算补齐字节。没有动态内存或整包RAM缓存。

成功输出的76B版本载荷已带目标槽CRC，供后续B受控保存；此函数本身不写W25版本记录/FRU。
**返回成功仅表示安装读回通过，不是TRIAL提交、跳转或30秒健康确认。** 失败时输出清零，
保留目标无效状态；不自动重试或交换两槽。持久化日志未接入前，默认B不得调用安装函数。

真实硬件端口仍需：有限超时、基于进展喂狗、同bank擦写完整RAM执行路径、ECC异常处理、
边界二次保护及安全跳转环境。模拟回调不代表这些硬件能力已经存在。

## 本轮验证

- Debug/Release各142项：实际C核心在QEMU Cortex-M7执行；另各4项发布工具反例检查。
- 两方向安装、7个逐扇区半擦除失败点、19个逐Flash-word半写失败点均检查原槽保护及同目标重装。
- 两遍源读取共19个失败点、内部读取失败、状态提交失败、读回向量/CRC损坏、验证后源包变化。
- 包头/元数据/板型/版本/长度/坏表、非对齐跨边界、RAM空洞、复位入口、16B至896KiB边界。
- 当前Debug App 220812B、1722项修正，包227816B；Release 130428B、1215项修正，包135404B。
  C模拟安装A1/A2分别与原始/转换App逐字节一致。
- 默认B的Debug/Release构建通过，仍是原最小跳转；核心只编入`libota_core.a`。

复现：`tools/dev.ps1 ota-test -AppBuild ../test/build/ota-probe-debug-a1`；
Release增加`-Configuration Release`并改为相应App目录。报告在`build/*-ota-test/report.json`，
记录C源码/测试ELF及各输入包SHA-256。测试镜像不可烧录到STM32。

QEMU使用[MPS2-AN500 Cortex-M7模型](https://www.qemu.org/docs/master/system/arm/mps2.html)，
本测试自行用RAM模拟Flash，不模拟H743的Flash/QSPI外设。RAM白名单核对了项目链接脚本及
[ST的H743设备内存定义](https://github.com/STMicroelectronics/cmsis-device-h7/blob/master/Include/stm32h743xx.h)。
这些是离线算法证据，不是W25读取、同bank写入、ECC恢复或真实断电验收。本轮未烧录、未推送。
