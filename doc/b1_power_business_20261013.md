# B1初版电源业务配置（2026-10-13）

## 已确认并实现的规则

本记录替代旧设计中“训练白名单/业务等待/RK适配器仍未配置”和“等待RK允许安全关机”的部分。仅首次装载配置，不在MCU上电时自动打开RK电源。

| 项目 | 当前规则 |
|---|---|
| 训练电压 | PC确认具体DDR允许的电压范围和三轨组合；MCU精确设置合法目标，不附加训练白名单，不取整或钳位 |
| MCU输入校验 | memoryType、字符串格式、TPS可写范围和原生步进仍必须正确；非法请求在操作硬件前回invalidArgument |
| TPS范围 | VDD1：800～3350mV、10mV步进；VDD2/VDDQ：400～1675mV、5mV步进。仅表示可编码，不表示DDR安全 |
| RK初始化完成 | 本次启动后收到CRC有效的普通串口心跳；RK必须在初始化完成后才发心跳 |
| 下电 | 直接调用既有关电驱动，不发送关机TLV、不等RK关机应答；不代表RK已停止存储写入 |
| B2 | 保活/IP通知等B2合同等工程师参与，不新增SPI业务 |
| IDD | 等RK给出算法/状态保持/测量窗口实现方式，21～36仍不宣称支持 |

power仍表示训练电压，不是训练完成后拉偏。PC6给RK806和TPS共同供电，软件仍以“天然窗口内来得及写目标”为开发预设；心跳到达不能证明上电期间三轨始终符合JEDEC要求。

## 配置入口与初值

B1 Core/Inc/board_power_config.h同时保存低层时序和业务等待，Core/Src/main.c装载并绑定rk_link_ready_begin/poll。

| 参数 | 初值 | 含义 |
|---|---:|---|
| first_to_second_delay_ms | 10ms | PC7开3.3V后，再开PC6的4V |
| second_to_tps_config_delay_ms | 5ms | 4V使能后开始访问TPS的初始等待 |
| system_rail_off_spacing_ms | 10ms | 先关PC6，随后关PC7 |
| off_hold_ms | 500ms | 两路均OFF后停留，不能当作实测放电完成 |
| boot_settle_ms | 10ms | Boot DAC成功写完后等待，再开启电源 |
| transition_timeout_ms | 2000ms | 等低层上/下电动作完成的上限 |
| ready_timeout_ms | 60000ms | 状态ON后等待本轮RK心跳的上限，不是算法运行超时 |

这些是可调联调值，不是器件标准或硬件验收值。低层由默认任务推进，业务由现有TCP任务查表推进，不新增任务。同步I2C调用、调度及锁等待会影响实际用时。

## 正式命令行为

| 命令 | 行为 |
|---|---|
| 0501 | 使用已保存的训练目标上电；无特别目标时标称。电源状态ON后completed，仅表示电源流程完成 |
| 0502 | 不等RK应答，先关4V再关3.3V，状态OFF后completed；算法/维护在途仍busy |
| 0505 | 直接关电→500ms停留→保留Boot/训练目标重新上电→本轮心跳→completed |
| 完整0103 | 必要时直接关电→OFF停留→写Boot→等稳定→上电写三轨训练目标→本轮心跳→入RK算法队列 |
| 外部就绪0103 | 原power:null、bootMode:null、reboot:false不变；B1仍要求ON及操作者确认RK可执行 |
| 0509 | 保留运行期调压合同；OFF仅接受标称值，不能用它替代0103训练启动 |

完整0103保持“0006 accepted → 0006 completed → 0105”关系。completed不是算法结束；配置改变或reboot=true仍会冷启动，同配置且有本次运行的成功就绪记录才复用。

MCU仍保留OTA健康确认、测试/升级互斥、驱动错误和阶段超时。下电驱动锁忙返回busy，不无界重试；上电失败不投递算法；心跳等待超时回timeout，保持当前电源状态供诊断，不擅自反复切电。低层转换超时不代表动作被撤销，应查询状态。B1始终无MATS假FAIL。

## 心跳怎样排除旧数据

1. 上电前用非0内部token清除上一轮就绪记录；token不增加到PC JSON或RK TLV。
2. RK任务在电源ON时按原1秒周期发普通心跳；仅成功进入UART发送队列的Seq更新就绪窗口。
3. RX经原帧状态机检查长度、HCRC、FCRC和帧尾后，零TLV心跳（兼容0x0000空Value）才可参与确认。
4. RK携带的Seq须位于本轮首个至最近成功发送心跳的窗口，允许定时器造成的滞后和重复；旧启动、未来Seq、坏CRC、进度、最终结果或打印文字不能放行。

这是初始化完成的项目约定，不是独立的DDR训练验收或密码学防重放。RK若在真正可执行算法前就开始发心跳，双方仍须修正发送时点。
