# B1 外设验板工具

复用当前固件的050x/060x。PAC只提供电流，AD7124提供电压；未增加协议字段，不发送RK算法、OTA或温控命令。

2026-11-04版配套B1新固件：0509在OFF保存下次上电目标，0501在上电初期写入目标。旧固件会拒绝OFF非标称值，工具遇拒绝即停止，不退回标称启动。该语义本轮只修改B1，V2未同步。现有运行中的旧EXE未替换，新工具交付在`build/b1-debug-off-target-20261104/`。

## 打开与使用

本次成品：`D:\pro\test\build\b1-debug-off-target-20261104\JMCT_B1_Debug.exe`，双击打开，无须安装Python；窗口标题含“OFF目标上电”。交付压缩包为`build\JMCT_B1_Debug_OFF_Target_20261104.zip`，含程序、说明及运行库许可。源码在本目录：`app.py`负责窗口，`core.py`负责TCP、循环和CSV。日常打包脚本仍输出到`build\b1-debug-tool`；该旧目录本轮未覆盖。

1. B1使用已接入050x/060x的正式固件、独立供电并接好网络。关闭其他PC/网络助手连接，保证RK可直接掉电、不在写盘。
2. 填入B1当前IP、端口8888，点击“连接 / 查询设备”。初次本地调试地址为192.168.1.201；B2配置后用实际地址。
3. 选内存类型和Boot模式。连接和查询不会自动上电；单步按钮只执行明确点选的动作。
4. 电压循环：填三路mV，点击“添加这一档”；设置清单循环次数、上电后等待及每档采样数，再开始。每一档都会重新下电、保存该档目标并上电，不再先按标称启动后调压。
5. Boot：选模式，填单步页或电压页共用的三轨输入框，以及循环次数、下电等待和上电观察时间，再开始。每次使用这组三轨目标；无需RK发送心跳。
6. 每次操作自动写记录，点击“打开记录目录”查看。默认目录为`%LOCALAPPDATA%\JMCT\B1Debug\reports`。

窗口内的仪表参考mV/mA是人工填写的参考读数，留空即可；不是自动连接仪表。每个电压点的参考值会复用于该点各次采样及循环。

## 单步与持续监测

- **单步上电/下电**：使用MCU当前配置，等待完成并查询逻辑电源状态；不暗中设置Boot、修改电压或冷重启。
- **设置Boot**：使用顶部选择，发送0506并用0507核对配置缓存。ON时的拒绝直接显示，不自动下电。
- **应用三轨电压/类型**：发送输入框的三个绝对mV值。OFF时只保存内存类型和下次上电目标，不访问TPS；ON时同类型立即调压，不覆盖下次上电目标。上方选择框或“填入标称值”仅改变窗口输入，点击应用才提交。
- **首次单步顺序**：确认OFF和三轨放电 → 填入/应用本次目标 → 设置Boot → 上电 → 只读监测及保存RK日志。首次用标称1800/1100/600mV，单次启动通过后再测其他档和重复启动。单步页和循环页共用三轨输入，循环清单仍需手动添加。
- 目标仅保存在MCU RAM，RK/DDR下电后保留，MCU复位后恢复标称并需重新设置Boot。ON时再点“上电”不会重启；要验证新目标启动，必须先下电再应用目标。
- **持续监测**：只轮询0601，默认500ms，可选100～60000ms。AD/PAC分别检查有效位，OFF、缺失、格式错误或快照年龄超过1500ms的数据显示“—”，不冒充零。停止收到新数据后，屏幕上的年龄仍继续增加并显示过期。
- 两幅曲线分别显示mV和mA，最多保留最近300次查询，失效处断线；全部查询正文存JSONL，三轨读数/失效原因逐行存CSV。这里的行号是查询次数，不是ADC转换次数，不额外计算测试平均/峰值。
- 开始持续监测后自动收起设置区以展开曲线；停止后点击“展开设置”可继续调压。也可随时手动收起/展开。
- 持续监测和控制操作串行，先点击停止再做设置。停止或关闭监测不下电，底部下电勾选项只适用于调压/Boot循环；没有偷偷恢复或重连。

## 电压范围

| 电源轨 | 开放范围 | 步进 |
|---|---|---|
| VDD1 | 800～3350mV | 10mV |
| VDD2 | 400～1675mV | 5mV |
| VDDQ | 400～1675mV | 5mV |

只限制TPS编码范围和整步，不限制为DDR安全电压；不取整、不自动扫完整范围。可写不等于板上负载安全，操作者根据实物选择组合。工具不自动判断精度合格与否。

两种循环都在OFF通过0509保存目标后再0501上电，复用固件已有训练目标缓存及写入路径，不发送010x测试命令。LPDDR4X标称1800/1100/600mV，LPDDR4标称1800/1100/1100mV。

## 实际交互流程

| 操作 | 工具发送的流程 |
|---|---|
| 连接 | 0002心跳 → 0101信息 → 0503电源状态 |
| 单步上电 / 下电 | 0501 / 0502 → 0503确认状态 |
| 单步Boot | 0506 → 0507核对配置缓存 |
| 单步调压 | 0509，只设置输入的三轨值和类型 |
| 持续监测 | 串行重复0601；停止时不追加电源操作 |
| 电压循环每档上电 | 0502下电 → 0503确认OFF → 0509保存该档三轨目标 → 0506设Boot → 0507查缓存 → 0501上电 → 0503确认ON |
| 每档测量 | 上电后等待 → 0601查询新的有效采样 → 记录三路AD电压/PAC电流；上电后不再追加0509 |
| Boot循环每次 | 下电并确认 → 0509保存三轨输入框目标 → 额外下电等待 → 0506/0507设查Boot → 0501上电并确认 → 观察等待 → 再查Boot缓存和电源状态 |
| 收尾 | 正常结束或手动停止，按勾选项发送0502并确认OFF |

- 接到0006 accepted还会等待completed；不凭accepted推进，不按请求Seq匹配应答。两个方向的Seq各自递增。
- 普通命令等待上限5秒；任一失败或超时停止循环，不自动重发、重连或追加下电。发生通信超时后关闭TCP，执行状态未知。
- 手动停止会先收完已发送命令的应答，再按选项下电。窗口关闭时同样先停止。断开TCP本身不会下电；停止按钮不是硬件急停。
- 0602是最近快照。调压循环要求ON、AD和PAC均有效，并用sampleAgeMs保守排除稳定等待前或上次记录前的快照；10秒内无合格新采样则停止。持续监测允许保留部分有效读数，失效状态继续记录，通信错误则停止。
- 查询间隔是PC读取间隔，不修改MCU内部ADC采集速率，不代表捕获全部瞬态。有效快照的电压和电流也不是严格同时采样。
- 本工具不使用0505，因为该接口包含RK心跳就绪等待，不适合未烧SPL的验板阶段。
- 上电后等待时间只用于采样或人工观察，不会自动检测Linux启动终点。重复启动前先完成单次验证；需要完整日志时按实际启动耗时设置观察时间。

## 记录与验收边界

- `frames.jsonl`：配置、每帧方向/命令/独立Seq/JSON正文、结束或错误原因。
- `measurements.csv`：三路设定值、AD实测电压、AD减目标及百分比偏差、PAC电流、可选仪表参考与差值；每行立即刷新保存，Excel可直接打开。界面最多显示最近500行，CSV保留全部。
- 0508只表示成功配置的缓存，不是Boot电压实测。Boot记录的“目标mV”是DAC目标，不是DDR电压；“上下电结果=指令完成”不等于RK选定介质成功。实际启动介质统一记为“未验证”，需结合Boot电压测量、RK证据或启动总线观测确认。
- V2如果烧的是电源/测量模拟固件，读数仍为模拟；工具不能从无simulation字段推断为B1实测。记录用于实际硬件验收前，应确认板型与所烧固件。
- OFF预设只保证软件在TPS首次配置时直接写目标；PC6仍同时供电给TPS和RK806，三轨需顺序写入。没有新增硬件复位保持，不能宣称从通电瞬间即为目标或已赶在DDR训练前；仍需电压波形及完整RK启动日志验收。
