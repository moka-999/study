# 第二块阿波罗 V2：裸机 SPI 主机

仅用于模拟 B2，与运行正式任务的 V2 或 B1 互联。只有 USART1 命令行和 SPI3 主机；不含 FreeRTOS、lwIP、RK、ADC、W25Q256 或 OTA。

**此程序从 `0x08000000` 运行，只给第二块测试板使用。不要下载到已部署 Boot+App 的网关板，否则会覆盖 Boot。** 本次只编译及离线验证，未烧录、未接串口或 ST-Link。

## 1. 两块 V2 怎么接

两端信号同名直连，不交换 MOSI/MISO；两块板各自供电，只共地。

| 信号 | 第二块 V2（主机） | 运行网关固件的 V2（从机） |
|---|---|---|
| CS | PA15 / P2 第19脚 | PA15 / P2 第19脚 |
| SCK | PB3 / P2 第11脚 | PB3 / P2 第11脚 |
| MISO | PB4 / P2 第12脚 | PB4 / P2 第12脚 |
| MOSI | PB5 / P2 第13脚 | PB5 / P2 第13脚 |
| GND | P3 第1脚或板上 GND | P3 第1脚或板上 GND |

接线依据是本机阿波罗资料中的 `DNF429P_F767P_H743P V2.6.pdf` 第2页排针图；该页标题仍标 V2.5。接线前核对手上板子的丝印/版本，不按照片左右猜针号。PB3/PB4/PA15与摄像头接口共脚，PB5与LCD背光共脚：联调时拔掉这些外设，使用短杜邦线、3.3V逻辑，不并接两板3.3V/5V/12V，也不用 JTAG/SWO 占用 PB3/PB4。

SPI为 Mode 0、8位、MSB先行、CS低有效、1MHz。PB3/PB4的SPI3复用是AF6，**PB5的SPI3_MOSI是AF7**，不能统一设AF6；参见 [ST H743数据手册的复用表](https://www.st.com/resource/en/datasheet/stm32h743bi.pdf)。

改接实际 B1 时，主机侧不变；B1侧接 SPI2：PB12=CS、PB13=SCK、PB14=MISO、PB15=MOSI，并共地。B1连接器位置按其实际装配确认。

## 2. 编译与串口

从主工程目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/b2_spi_master/build.ps1
```

也可在 VS Code 单独打开本文件夹，按 Ctrl+Shift+B **只编译**。复用主工程的 ST HAL/CMSIS 和 GCC，不要求安装新工具链；此文件夹暂不能脱离仓库单独复制后构建。

产物位于主工程 `build/b2-spi-master/`：

- `b2_spi_master.elf`：调试及下载，含地址。
- `b2_spi_master.hex`：下载，含地址。
- `b2_spi_master.bin`：裸镜像，下载地址为 `0x08000000`。

烧录前必须确认选中的是第二块板，以及其中没有需要保留的固件。这里没有自动擦写/下载任务，避免误写现有 OTA 网关板。

第二块板 USART1：PA9=TX、PA10=RX、115200/8N1、无流控。使用板载USB转串口时按板上跳帽接到USART1；外接USB-TTL时TX/RX交叉、共地，不能接RS232电平。网关V2的USART1仍用于RK协议，不接到此命令行。

## 3. 命令

串口选择文本发送，每条以换行结尾；可以打开本地回显。

| 输入 | 功能 |
|---|---|
| `help` | 显示命令 |
| `query` | 只发0004，查询当前测试仪/槽位编号 |
| `id 3` | 保存期望testerId=3，并立即发送 |
| `mode 0 1` | 只通知mirrorIndex=0为高温模式 |
| `mode 1 0` | 只通知mirrorIndex=1为常温模式 |
| `poll on` | 每约1秒发送本主机已知编号和模式；默认开启 |
| `poll off` | 停止周期交换，手动命令仍可发送 |

`testerId`范围1～21，`mirrorIndex`范围0～2，模式0=常温、1=高温。未设置的镜像不发送，不会用默认0覆盖从机缓存。设置会保存在主机RAM，重启丢失。忙或超时后期望值仍保留，周期交换会用新的Seq再确认；若不希望继续尝试，执行 `poll off`。

响应中的 `status`：0成功、1参数错误、2忙、3不支持、4执行失败。超时打印 `UNKNOWN`，仅表示没拿到确认，**不证明从机没执行**。同一次交换最多3次写入，重试完全复用Seq和帧；每次写后等5ms，再读取应答。

## 4. 最小联调步骤

1. 先不上电接线；检查没有摄像头/LCD占用上述脚位，再给两板供电。
2. 串口发 `query`。未配置时应返回 `tester=0`；网关V2默认 `site=1`，B1为硬件槽位码加1。
3. 断开PC到网关的TCP连接，确认无测试、电源切换或升级在途；发 `id 3`。默认site=1时，应成功切到 `192.168.210.31:8888`。
4. PC网卡设置到同网段，不能与 `.31` 冲突，例如使用已确认的产线PC地址 `.9`。再连接新IP；不需要重新启动MCU。
5. 发 `mode 0 1`、`mode 1 0`。只缓存模式，不会开启加热。PC发0106 `{}`后，第一组为高温闪、第二组常温闪；未配置的第三组保持灭。
6. 整轮中可继续发单个 `mode` 检查局部更新；0107收尾后，周期SPI通知不覆盖最终PASS/FAIL灯。下次0106再按缓存模式显示。
7. PC连接存在时发送不同 `id` 应回2/busy；断开PC后，下一次周期交换才可生效。相同编号的周期交换不重复重配网络。
8. `poll off`超过3秒，网关诊断应离线；不会自动改温控模式、清IP或把结果灯改PASS。

换网段后如果无法连接，先检查PC网卡、子网掩码和从机返回状态，不要重复复位。当前联调IP不持久化，从机复位后回本地测试地址，等待主机再次配置。两块V2中只有网关板启用网口，裸机主机不初始化以太网。

## 5. 验证边界

已通过裸机构建，以及实际C的请求/响应编解码、CRC、重试缓存、CS状态机、业务门禁和灯态离线回归。真实SPI时序、NSS上升沿/DMA收尾、MISO三态、引线信号质量、实际IP切换和灯光仍需接线验收；日志打印成功不代替逻辑分析仪波形检查。
