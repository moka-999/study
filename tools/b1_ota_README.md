# B1 独立网络升级工具

用于已经首烧完整 OTA Bootloader 和 App 的 B1，不用于空白板或损坏板救砖。
无需正式 PC 上位机、工程源码、STM32 编译器或 ST-Link；电脑需要 Python 3.10 或更新版本（安装时启用 Python Launcher 或加入 PATH）。

## 给操作人员

1. 解压整个交付包到可写文件夹，不要直接在 ZIP 内运行。
2. 停止 RK 测试及 B2 加热；通过正常操作流程使 RK/DDR 电源为 OFF，断开正式 PC/网络助手。MCU 本身保持供电和网络连接。
3. 双击 `start_b1_ota.cmd`，选 **1** 查询，填写实际 B1 IP。只有一个 TCP 客户端可连接，不能同时开网络助手。
4. 再次打开工具，选 **2** 升级，填写 IP、选择 `b1.ota`，确认条件后输入 `YES`。
5. 等待“目标包、运行版本和健康确认均匹配”的成功提示。健康观察至少 30 秒，默认总观察约 180 秒。日志保存在工具旁的 `logs` 文件夹。

选 **3** 只检查本地文件，不连接设备。工具不会扫描 IP，不假定生产 IP；正式地址由 B2 通知 B1，测试地址只能按现场实际填写。

## 命令行

```powershell
# 只读查询；把 <B1_IP> 替换为实际地址
py -3 b1_ota.py query --host <B1_IP>

# 离线检查文件
py -3 b1_ota.py inspect --package b1.ota

# 确认空闲后升级已有文件，不在操作人员电脑上编译
py -3 b1_ota.py upgrade --host <B1_IP> --package b1.ota --confirm-idle
```

端口默认 `8888`，可用 `--port` 指定；日志位置可用 `--log-dir` 指定。命令失败时返回非零退出码。

## 拒绝或中断怎么办

| 现象 | 处理 |
|---|---|
| busy | MCU仍认为算法/电源业务在途，先核对正常结束流程；工具不清busy、不重启RK |
| notReady / 未健康确认 | 等待启动健康确认；持续不就绪需检查板卡，不强行升级 |
| 电源不是off | 先由原控制流程停止测试、关RK/DDR；工具不发送0502，也不代替PC操作B2 |
| 板型/CRC错误 | 重新取得B1正式`.ota`，不能拿V2包或改名的bin/axf代替 |
| 版本不高于当前 | 用更高版本重新构建，不提供强制降级/同版重刷 |
| finish前传输断开 | 本轮停止并关闭连接；查清原因后重新发起，从0开始，无跨连接断点续传 |
| finish已发送但未确认成功 | 工具只重连查询，不再写入或重发finish。保存日志、核对当前版本；不能把超时直接当成失败然后盲目重刷 |

现有查询不能证明硬件板型，操作人员必须核对IP对应B1；不能凭统一的测试仪名称判断。
工具先拒绝非`b1-h743`文件，MCU/Boot仍负责目标板型二次校验。0504是逻辑电源状态，不是实测电压。
初版CRC只检查完整性，不是签名认证；只使用可信渠道提供的固件。

B1升级会复位MCU，Boot会保持RK/DDR关电，升级后不会自动恢复测试或加热。
首次部署仍用专用首烧包；App/网口不可用时仍须SWD维护。B1实板升级及断电验收尚待板到。
